# スライド色合わせパズル 仕様書

ブラウザで遊ぶ、ステージ制の「寄せて消す」パズル。
手順を誤って詰ませてしまう失敗を楽しみ、やり直してお手本手数を目指すゲーム。

技術構成：Vite + TypeScript（vanilla-ts）、テストは Vitest、公開は Vercel。

---

## 1. 基本ルール

- 盤面は W×H のマス目。各マスは「空き」「壁」「ボックス（色つき）」のいずれか
- プレイヤーは上下左右のいずれかを選ぶ（スワイプ／矢印キー）
- 選んだ方向へ、すべてのボックスが**壁・盤面の端・他のボックスに当たるまで**滑る。壁は動かない
- 滑り終えた後、**同じ色が上下左右で3個以上つながっている塊**をすべて同時に消す（斜めは含まない。4個以上の塊は丸ごと消える）
- 消えた後に再スライドや落下はしない。次の操作を待つ
- 盤面が変化しない操作は手数に数えない
- ボックスがすべて消えたらステージクリア
- 1手戻す機能は**つけない**。やり直しは「リセット（最初から）」のみ

## 2. 詰み判定

詰んだら「もう解けません」と表示し、リセットを促す。

- 簡易判定：いずれかの色の残数が 1 または 2 → 確実に詰み
- 正確判定：ソルバー（後述）で現在の盤面から解けるかを探索。解けなければ詰み
- 両方を同じロジック（src/solver）で実装し、ゲーム内とステージ検証で共用する

## 3. 評価（メダル）

- 金賞：お手本手数（最短手数）ちょうど
- 銀賞：お手本手数 + `silverMargin` 手以内（初期値 2）
- 銅賞：それ以上でもクリア
- 各ステージの最高メダルは localStorage に保存（読み書きは try/catch で囲む）

## 4. データ構造

```ts
type Color = 'R' | 'G' | 'B' | 'Y' | 'P';

type Cell =
  | { type: 'empty' }
  | { type: 'wall' }
  | { type: 'box'; color: Color };
  // 将来のアイテム用に type を追加していく（例：{ type: 'item'; kind: 'bomb' }）

type Board = { width: number; height: number; cells: Cell[] }; // 行優先

type Direction = 'up' | 'down' | 'left' | 'right';
```

ゲームロジックは**不変データ**で扱い、`move(board, dir): Board` のように新しい盤面を返す純粋関数にする（ソルバーとテストが書きやすくなる）。

## 5. ステージデータ

```json
{
  "id": "1-1",
  "name": "はじめの一歩",
  "grid": [
    "R...R",
    ".....",
    "..#..",
    ".....",
    "R...."
  ],
  "par": 2,
  "silverMargin": 2
}
```

- 文字の対応：`.` 空き、`#` 壁、`R G B Y P` 各色のボックス
- `par` は手書きしない。検証スクリプトが計算して書き込む

## 6. ソルバーとステージ検証

- 幅優先探索（BFS）。状態は盤面を文字列化したキーで重複排除
- 色の残数が 1〜2 になった状態は枝刈り
- 探索状態数に上限を設け、超えたら「判定不能」として扱う
- `npm run verify-stages`（scripts/verify-stages.ts）で全ステージを検証し、
  - 解けないステージをエラーとして報告
  - 最短手数を `par` に書き込む
  - 最短手順も出力（デバッグ・お手本表示用）

## 7. 画面・操作

- 盤面は `min(90vw, 90vh)` 程度で画面に合わせる。盤面に `touch-action: none`
- 入力：`pointerdown` / `pointerup` でスワイプ判定、キーボードは矢印キーと WASD
- 1手の演出（試作 yose-puzzle.html で確定済み。数値もこれを基準にする）
  1. 押した方向へ盤を3D風に傾ける（perspective 900px、約8度、約110ms）
  2. 全ボックスが加速しながら滑る（時間＝90ms＋移動マス数×55ms、ease-in系のカーブ）。止まったボックスは軽くつぶれて着地
  3. 揃った塊がふくらんで消える（約340ms）
  4. 盤を水平に戻す（約120ms）
  - 動けない方向を押したときも盤だけ軽く傾けて戻す（手数は増えない）
  - 演出中は入力を受け付けない
  - prefers-reduced-motion のときは傾き・移動・パーティクルを省略
- 表示：ステージ名、現在の手数、お手本手数、リセットボタン
- クリア画面：メダル、手数、次のステージへ
- 詰み表示：「もう解けません」＋リセット
- ステージ選択画面：各ステージの獲得メダルを表示

## 8. ディレクトリ構成

```
src/
  game/      盤面・移動・消去・クリア判定（DOMに依存しない純粋ロジック）
  solver/    BFSソルバー、詰み判定
  stages/    ステージJSON
  render/    DOM描画・アニメーション
  input/     スワイプ・キー入力
  storage/   メダルの保存
scripts/
  verify-stages.ts
tests/       Vitest（移動・消去・ソルバーを中心に）
```

## 9. 難易度の段階

1. 5×5、1〜2色、壁なし（ルールを覚える）
2. 3色に増やす
3. 壁ブロックを置く
4. 同じ色を6個・9個にして「3個ずつ分けて消す」ステージ（消しすぎの罠）
5. 盤面を広げ、お手本手数を増やす
6. アイテム導入（今後検討）

## 11. ビジュアル（POPで賑やかに）

- 全体の世界観：遊園地・お菓子・キラキラのPOPなデザイン。明るく賑やか
- 背景：遊園地モチーフ（ストライプのテント、観覧車、風船、星、紙吹雪など）をCSSとSVGで描く。ゆっくり動く装飾があってよいが、盤面の視認性を最優先
- 盤面：お菓子のトレイやショーケースのような枠。マスは淡い色、壁ブロックはビスケットやレンガ風
- ブロックは色ごとに別のモチーフにする（色だけでなく形でも区別できるように）
  - 赤：ロリポップ（うずまきキャンディ）
  - 青：宝石（カットされたジュエル）
  - 緑：魔法のステッキ（星つき）
  - 黄：キャンディ（包み紙）
  - 紫（将来用）：ハートのジュエリー
- モチーフは画像ファイルではなく SVG で描き、コンポーネント化（src/render/motifs.ts など）。ツヤ・ハイライトをつけて可愛く
- 画面サイズは 6×6 盤がスマホ縦画面に収まること
- フォントは丸みのあるもの（Google Fonts の Zen Maru Gothic など）

## 12. サウンド

- 音はすべて Web Audio API で合成して鳴らす（音源ファイルなし・ライセンス問題なし）。後から音源ファイルに差し替えられるよう、src/audio/ に「効果音名 → 再生関数」の形でまとめる
- BGM：遊園地のような明るく楽しいループ曲（メリーゴーラウンド風の3拍子、オルガン・ベル系の音色）。シーケンサー的に音符データで持つ
- 効果音
  - 傾ける：軽い「シュッ」
  - ボックスが止まる：コトッという小さな着地音（同時に複数止まっても鳴らしすぎない）
  - 消える：キラキラした上昇音（チャイム・グロッケン系）
  - 動けない方向：小さな「ぽよん」
  - 詰み：残念な下降音
  - クリア：成績に応じたファンファーレ（下記）
- ブラウザの自動再生制限があるため、最初のタップ／キー操作で音を開始する
- BGM と効果音それぞれにオン／オフボタン。設定は localStorage に保存（try/catch）

## 13. 演出

- ブロックが消えるとき：星がはじけて飛び散るパーティクル（canvas レイヤーで描画）＋キラキラ効果音
- ステージクリア時、メダルに応じて段階をつける
  - 金：大きな王冠と「PERFECT!」、花火＋紙吹雪を画面全体に、豪華なファンファーレ
  - 銀：「GREAT!」、紙吹雪と星、明るいファンファーレ
  - 銅：「CLEAR!」、小さめのキラキラ、短いジングル
- クリア画面：メダル、手数／お手本手数、「次のステージへ」「もう一度（金を狙う）」
- パーティクル数には上限を設け、スマホでも60fpsを保つ

## 14. 端末の傾き操作（スマホ・タブレット）

- DeviceOrientationEvent で端末を傾けて盤を傾けられるようにする
- iOS は DeviceOrientationEvent.requestPermission() をボタンのタップ時に呼んで許可をもらう。対応していない端末ではボタンを出さない
- 約20度以上傾けたら、その方向へ1手滑らせる。水平近く（約8度以内）に戻すまで次の手は受け付けない
- 開始時の持ち方を水平とみなす「水平リセット」ボタン
- 傾けている間は盤の3D表示も実際の角度に合わせて傾ける（最大8度程度に制限）
- 画面の回転ロックを促す案内を最初に一度表示する
- 傾き操作は設定でオン／オフ。スワイプ・矢印ボタン・キー操作は常に使える
- しきい値の角度は定数にまとめ、実機で調整しやすくする
- 確認は Vercel（HTTPS）に公開した後に実機で行う

## 15. 特殊アイテム（ステージ9〜32）

ステージは全32面。32面目をクリアすると全ステージクリアの演出を出す。
アイテムの挙動は docs/prototype.html の slide() / findGroups() / surelyStuck() が正。

### レインボーキャンディ（9面〜、ステージ文字 `*`）
- ボックスの一種。普通のボックスと同じく滑る
- どの色とも揃う。色 c について「c のボックス＋レインボー」でつながった3個以上の塊があり、その中に c のボックスが1個以上あれば、その塊が消える
- レインボーは隣り合う複数の色の塊に同時に参加できる（両方の塊が消え、レインボーも消える）
- レインボーだけで3個以上つながった塊も消える
- クリア条件は「レインボーも含めてボックスが全部消えること」
- 確実な詰み：ある色について「その色の数＋レインボーの数」が3未満。または色のボックスがなくなり、レインボーだけが1〜2個残った

### はちみつ床（13面〜、床レイヤーの `h`）
- 床に敷かれたマス。ボックスはその上に乗れる。壁ではない
- 滑ってきたボックスが、はちみつ床に入るとそこで止まる（進路上で最初に出会ったはちみつ床）
- 手の開始時に、すでにはちみつ床に乗っているボックスは止められない（離れられる）
- 後ろから来たボックスは、止まったボックスの後ろで止まる
- 演出：はちみつで止まったボックスは「ぺたっ」とつぶれる着地にし、効果音も変える

### 盤面データの2層化
- ボックス層 `grid`（`.` 空き、`#` 壁、`R G B Y` 色、`*` レインボー）と、床層 `floor`（`.` 普通、`h` はちみつ）に分ける
- 床は動かないので、ソルバーの状態キーにはボックス層だけを使う
- `floor` は省略可（省略時はすべて普通の床）

```json
{
  "id": "13",
  "name": "はちみつ床",
  "grid":  [".....", ".....", "R....", ".....", "..RR."],
  "floor": [".....", "..h..", ".....", ".....", "....."],
  "intro": "honey"
}
```

### 初登場の紹介
- `intro` を持つステージ（9面 rainbow、13面 honey、21面 both）では、最初の1手を指すまで新アイテムの説明を表示する

### ステージ構成（全32面、各面のデータは docs/stages.json）
- 1〜8：基本（ルールを覚える → 消しすぎの罠 → 6×6）
- 9〜12：レインボーキャンディ
- 13〜20：はちみつ床（壁と組み合わせ、6×6へ）
- 21〜24：レインボー＋はちみつ
- 25〜31：4色、レインボー複数、6×6の難関
- 32：7×7の最終ステージ
- どの面も「最短手順の中でアイテムが実際に効いている」ことを確認済み

### 詰み判定の負荷
- 詰み判定は毎手ソルバーを実行する。試作では最悪でも0.3秒程度だったが、スマホで重い場合は Web Worker で実行し、判定中も操作の演出は止めない

## 16. ヒント

- 「ヒント」ボタン（キーボードは H）で、今の盤面からの最短手順の次の1手を示す。ソルバーをそのまま使う
- 表示：盤の上に大きな方向の矢印を約1.6秒出し、対応する方向ボタンを光らせる。次の手を指すと消える
- 押すたびに1手ずつ教える。回数は画面に表示する
- ヒントを使ったステージは最高でも銀賞（金賞は自力のみ）。クリア画面で「次はヒントなしで金賞を」と促す
- 詰んでいる盤面ではヒントは出さない（詰み表示とやり直しで対応）
- ヒントの計算もソルバーなので、重い場合は詰み判定と同じく Web Worker で実行する

## 今後の検討メモ

- アイテム案：動かないボックス、どの色とも揃うボックス、一直線でないと消えない色、など
- 一直線ルールは特殊ステージやアイテムとして使う
- 消え方の判定は関数ひとつに閉じ込め、差し替え可能にしておく
